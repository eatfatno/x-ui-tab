# 3x-ui v3.9.0 → v3.10.2 升级评估

本文保留升级前静态评估。实施与验证结果见 [v1.0.2 升级说明](upgrade-v1.0.2.md)。

评估日期：2026-10-15（Asia/Shanghai）。当前 x-ui-tab 发布版为 v1.0.1，内置官方 3x-ui v3.9.0。

## 结论

对本项目现有的单机流量监测和 VLESS + TCP + REALITY 用途，预计属于**代码改动较小、完整交付工作量中等**的升级。主要改动是页面版本适配、构建版本配置与验收，现有监测服务、域名规则和 7/35 天存储方案预计可沿用。

不能只替换官方面板文件就认为升级完成：现有前后端适配器只接受 3.9.x，直接运行 3.10.2 时不会注入监测侧栏入口。需在新版真实页面验收通过后，将其加入兼容版本范围。

本次完成发布记录、源文件哈希和关键代码差异检查，未安装或运行 v3.10.2，也未修改运行配置、数据库、现有镜像或已发布安装包。以下兼容性判断属于静态评估，不能代替新版运行验收。

## 官方版本与相关变化

- 最新正式版：[v3.10.2](https://github.com/MHSanaei/3x-ui/releases/tag/v3.10.2)，北京时间 **2026-10-14 23:19:26** 发布。
- 中间版本：[v3.10.0](https://github.com/MHSanaei/3x-ui/releases/tag/v3.10.0)，包括 Xray-core v26.10.10、MASQUE、XDRIVE、配置迁移和节点同步修复。
- 对当前用途有直接价值的变化：VLESS Vision 的适用条件修正、REALITY 链接二维码修复、Xray 崩溃日志记录改进。
- v3.10.2 的客户端热更新、减少节点同步写入等优化主要面向 Shadowsocks 或多节点；不能据此推断本项目单机内存和 CPU 会明显下降。
- 官方 Windows 程序重命名不影响 Linux Docker 部署。官方 Linux amd64 发行包名称仍为 `x-ui-linux-amd64.tar.gz`，约 79.66 MiB；包内文件布局需在后续打包时验证。

## 需要改动和重新验证的内容

| 部分 | 已确认的依据 | 预计工作 |
| --- | --- | --- |
| 监测 Tab 与页面集成 | `adapter.js` 和后端 `compatible()` 均限制 3.9.x。上游 PanelLayout、IndexPage、OverviewActionBar 和首页 CSS 的文件哈希未变；AppSidebar 的差异为移除赞助卡片 | 小：调整兼容版本范围，验收桌面、手机、主题、刷新及前进后退 |
| 登录、会话与安全响应头 | 上游会话、CSRF、安全中间件和 HTML 入口控制器哈希未变；API 鉴权文件的变化仅为 node-sync 权限新增三个路由 | 预计无需重写：复测未登录、退出、会话过期、同源删除和 HTTPS |
| 客户端采样与实时在线 | 客户端控制器、客户端列表查询及序列化文件哈希未变，`id`、`createdAt`、`inboundIds` 和 `traffic` 的读取合同仍可沿用；状态控制器未变 | 预计无需重写：验证两名以上客户端上传/下载归属、在线状态、重置和重启后的采样基线 |
| Token 与入站映射 | `admin` Token 和浏览器会话的权限行为未变；入站控制器只增加节点主控请求标记的处理。`monitor` scope 仍不包含完整客户端列表 | 保留现有服务端采集凭证方式，复测列表和标签映射 |
| Xray 日志和持久模板 | 默认 `config.json` 哈希未变，现有访问日志路径、LoggerService 与内部 API 配置方式预计仍适用；Xray 已换版本 | 中：用新版内核实际产生 VLESS/TCP/REALITY 流量，检查域名、客户端归属、日志格式和轮转 |
| 官方数据库升级 | 新版增加 xdns、udpHop、Host 证书字段和 Shadowsocks 配置修复/迁移 | 中：从旧数据库副本启动，检查配置、客户端和累计值；验证失败时恢复旧镜像与升级前数据 |
| 监测历史与规则 | 独立数据库和规则文件不依赖官方数据库的这些迁移，目前未发现必须改表的理由 | 以真实监测历史验证保留、分钟查询和删除，不能只用空数据库或占位数据证明兼容 |
| Docker 和发布 | 当前构建已支持 `PANEL_VERSION`、`MONITOR_VERSION`，管理菜单已有一致性备份和升级失败恢复 | 小到中：更新默认版本、获取并校验官方包、构建新镜像、发布新的 x-ui-tab 版本并验证安装 |

## 本地预计涉及的位置

- `apps/traffic-monitor/web/public/adapter.js`：前端版本判断；若真实新版 DOM 符合静态检查结果，现有选择器可沿用。
- `apps/traffic-monitor/internal/monitor/store.go`：后端兼容判断，控制注入和健康状态。
- `apps/traffic-monitor/internal/monitor/config.go`：默认面板版本提示。
- `scripts/build-docker.sh`、`scripts/prepare-docker.py`、`deploy/docker/compose.yaml`、`deploy/docker/x-ui`：默认版本及镜像标识。
- `scripts/install-online.sh`：随新 x-ui-tab Release 更新默认发布标签。官方版本号与本扩展版本号分别管理。
- 前后端适配测试、Docker/浏览器验收和升级测试：现有 `test-official-upgrade.py` 验证的是 3.8.5 → 3.9.0，不能作为本次 3.9.0 → 3.10.2 的通过记录。
- README、版本说明、第三方组件说明及校验清单：与实际交付版本一致。

本项目使用官方编译好的 Linux 发行包，官方源码所需 Go 1.27.2 不等于必须重写或重新编译整个官方面板。新版包沿用“官方发行包 + 所需纯文本配置/许可”的构建方式。

## 实施建议

1. 保留现有 v1.0.1 安装包，在项目内建立隔离的 3.10.2 测试部署，使用独立端口和数据副本。
2. 完成版本适配和新镜像构建，先验证初始化、登录、Token、采样和页面集成。
3. 使用旧版本产生的真实监测数据验证升级，覆盖官方数据迁移、历史连续性及失败恢复。数据库已被新版迁移后，回退使用升级前的一致性备份。
4. 验证 VLESS + TCP + REALITY 的实际代理、请求目标识别、实时流量、记录删除、日志轮转，以及原面板的编辑/二维码等功能。
5. 在原 1 核 / 1 GB、最多 5 台设备的目标下复测峰值与空闲占用；原有资源报告保留其原版本适用范围。
6. 验收通过后，可将新版作为 x-ui-tab v1.0.2 发布，内置官方 3x-ui v3.10.2，通过本项目镜像更新流程交付。

MASQUE、XDRIVE、TUN 等上游新增或扩展功能不自动等同于本 Docker 包已完成支持验收；若要把这些功能纳入交付，应分别检查目录挂载、网络权限和流量统计方式。当前评估针对已经交付的单机监测和 VLESS/TCP/REALITY 场景。
