# 域名规则、目标汇总与删除历史

本次更新按“日志目标域名 → 本地规则集 → 服务名称”识别常见服务。无需运行时联网下载规则，也不做反向 DNS 或按共享 IP 猜测网站。全部源代码、规则快照、运行数据和测试产物位于项目根目录。

先匹配精确主机名，再按由长到短的域名后缀匹配；后缀必须位于完整标签边界，例如 `github.com.evil.test` 不会命中 GitHub。精确规则仅匹配该主机，不自动包含子域名。显示服务名称时保留原始目标，方便核对。规则识别包含服务的接口、静态资源、CDN 等域名，不能证明用户实际看了某个网页；“已接受”也不保证网页加载成功。

导入器保留每个服务文件的直接规则归属，不将母公司的 `include` 列表全部归为母公司，因此 YouTube 与 Google、GitHub 与 Microsoft 分开。路由地区、通用分类及注册局 TLD 列表不作为服务名。无法安全解释的正则/关键词规则（23 条）与归属有歧义的冲突（12 条）跳过，统计在规则文件中记录。

## VLESS + TCP + REALITY 的目标来源

REALITY 的 `serverName` / 分享链接 `sni` 是握手伪装目标，不代表用户实际访问的网站。使用 `xtls-rprx-vision` 的 VLESS TCP REALITY 入站仍会记录所代理的真实域名/IP，监测从 access log 读取这些目标并匹配服务规则。只有通过该入站的连接才能被这个实例记录。

客户端直接传递域名时，百度、GitHub、YouTube 等可以正常归类。实测 Xray v26.9.30 中，客户端传 IP、服务器开启 `http/tls/quic` 嗅探及 `routeOnly:false`，access log 仍可能只保留原 IP。开启客户端嗅探并在进入 VLESS 隧道前恢复域名后，本次百度 HTTPS 测试成功记录 `www.baidu.com`。这不承诺所有 App 都能恢复：没有可用域名、加密 ClientHello 或不支持的协议仍显示 IP。客户端 DNS/fake-IP/嗅探选项随软件不同，应以最终日志核对，不根据共享 IP 或 REALITY SNI 猜测服务。

页面默认今天。日期内没有访问、但近 7 天内有其他访问时，会显示最近访问时间和“查看最近访问当天”。如果日常设备使用远程服务器，本地 WSL 页面不会自动获得那台服务器的日志；需要在对应服务器接入采集。

## 目标汇总

默认打开“目标汇总”，旁边可以切换“访问明细”。汇总以“客户端稳定身份＋服务组”分组，未知服务按实际主机名分组。localhost 和回环 IP 合并到本机目标，同一客户端的 19090、19091 等不同端口合并为一行。不同客户端保持分组；未匹配身份的不同 email 也分别显示。

每组提供访问次数、涉及的原始目标数量、端口、协议、入站、首次和最近访问时间。服务名、域名、IP 搜索同时作用于目标汇总和明细。目标列表及元数据每组最多返回 50 个不同值，域名/IP 总数量独立返回。查询在数据库中分组后分页，浏览器不加载全部日志。

目标汇总基于现存逐条记录，因此仅覆盖 **7 天**；第 8～35 天仍有客户端上传/下载和访问次数汇总，无法查看目标。字节数来自客户端累计采样，无法精确分配给单个域名，目标表以访问次数呈现，上方流量卡片与趋势呈现客户端用量。

## 分钟筛选

查询和删除弹窗都使用 `YYYY-MM-DD HH:mm`，以北京时间解释，**包含结束分钟**。例如 `2026-10-09 09:30` 至同一时间表示 `09:30:00 ≤ 时间 < 09:31:00`；选至 `09:45` 则包含整个 09:45 分钟。API 继续使用 UTC `[start,end)`。今天默认 00:00～23:59，提供最近 1 小时、昨天、最近 7/35 天快捷项；最长实际区间为 35×24 小时。

客户端流量本身是采样后的分钟用量，无法精确到秒或按单条访问分摊。长时间范围的图表会合并为小时/6 小时显示，但筛选先按指定分钟执行，不会把筛选范围外的流量计入合计。上方流量卡片及趋势只应用时间、客户端和入站条件；目标搜索只筛访问记录。

页面每次请求结束后等待 30 秒再自动刷新，隐藏页面或删除弹窗打开时暂停自动刷新，仅查询当前打开的目标汇总或明细。后台每 10 秒采集保持不变。闲置客户端仍刷新采样基线，但不写入全零流量桶。资源测量及局限详见 `resource-assessment.md`。

## 删除日志与监测流量

客户端选择框默认只显示原面板中仍存在的客户端；需要查询或删除旧客户端的历史时，勾选“显示历史客户端”。同名历史身份标注最后同步时间和身份编号，避免删除重建后无法区分。历史条目的最后一段明细/流量/访问次数全部清空或到期后，会自动从选项中消失；后台必要的身份映射和防止重新导入的记录继续保留。

“所有客户端”始终覆盖历史客户端和未匹配记录，不受显示开关影响。删除监测日志不会删除原面板中的客户端，因此仍在官方列表中的同名客户端会继续正常显示。

1. 点击“删除日志与流量”，选择一个客户端或所有客户端及日期范围。
2. 点击“预览删除范围”，核对具体时间、客户端数量、明细条数、汇总访问次数、分钟流量记录及上传/下载/合计。
3. 勾选范围确认并点击“确认删除”。明细、目标汇总、访问次数、流量卡片和趋势一起刷新。

删除按“客户端＋日期范围”执行，覆盖该范围内所有目标和入站。查询框中的域名或入站筛选不会缩小删除范围，弹窗明确说明并重新选择范围。单条访问日志没有字节数，不能从客户端用量中准确扣除某一个目标。

删除明细、35 天访问次数汇总和分钟流量时使用同一个数据库事务。第 8～35 天虽然没有明细，仍可以删除该日期的用量与访问数量。数据库会留下“已清理历史”质量标记，不把手动清理伪装成自然没有访问。

删除不重置官方累计计数或客户端限额。采样基线和读取检查点保留，删除范围阻止迟到记录、复制日志、重启后重读数据再次进入历史。Xray 原始文件仍最多保留 7 天，这个按钮清理的是监测数据库中的历史，不是对原始文件做物理擦除。

采样粒度为分钟，因此包含当前日期的删除预览将截止时间冻结为**当前分钟结束**。确认后该分钟中晚到的记录也将忽略；跨越删除边界的首个采样增量不能拆分，作为基线处理，后续采样恢复。不会忽略今天尚未发生的其余时段。

预览有效期为 5 分钟，令牌只属于当前浏览器会话、只能使用一次；服务重启后需重新预览。数据库记录发生变化时返回 409，要求重新预览，避免确认与实际影响范围不一致。提交还检查当前登录状态、同源 Origin、JSON 类型和专用防伪头；后台采集 Token 不提供删除权限。

## 合计流量与实时在线

按最新确认，页面已移除“面板累计”卡片与清零入口，保留“合计流量”。合计使用所选分钟范围内的采样上传加下载；删除该范围的监测历史会同步扣除合计。清理所有保留历史时，在删除弹窗选择“所有客户端”和覆盖保留期的时间范围，预览后确认。原官方面板的配额计数仍由 3x-ui 管理。

“实时在线客户端”展示客户端、在线状态、上传速度、下载速度、本轮上传、本轮下载。速度为最近一轮采样的平均字节数/秒，本轮流量为这段约 10 秒间隔内的上传/下载字节数，涵盖客户端全部连接。它应用客户端和入站筛选，独立于历史日期与目标搜索。默认仅显示在线客户端；关闭开关可查看离线客户端，在线状态未知的客户端始终保留以提示异常。

实时在线状态来自 3x-ui 的缓存名单；活跃但暂时没有字节传输的连接可以保持在线。短连接关闭后，可能要等官方下一轮更新才转为离线。刚启动时等待两次采样建立速度；计数回退、采集失联或超过 3 个采样周期时，无法确定的速度显示“—”。这不是逐连接或逐域名的精确实时计量。

后台复用原有 10 秒流量采样，另读取一次固定在线名单接口；结果只保存在内存，页面每约 10 秒读取。没有按访问记录追加流量明细，也不执行反向 DNS。域名文字放大至 14px，使用更高对比度，长域名自动换行。

兼容官方 3.9.0 创建时间精度变化：首次编辑/启停客户端可能把创建时间从毫秒截到整秒。监测对身份中的创建时间统一采用秒精度，避免把同一客户端误判成删除重建。启动时以事务合并旧格式键的历史、计数和基线，原删除范围继续生效。官方客户端数字 ID 不同、创建秒不同或实例不同的身份仍分开。
