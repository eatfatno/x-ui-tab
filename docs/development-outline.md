# 3x-ui 流量监测 Tab 开发大纲

确认日期：2026-10-08（Asia/Shanghai）。本文记录用户批准的实施边界；实际验证结果见环境检查及测试报告。

## 目标与口径

在官方 3x-ui 的侧栏增加“流量监测”，保留原侧栏和顶部，在右侧嵌入独立监测页面。首版只处理单台服务器，先在 Ubuntu-24.04 WSL 验证。访问记录按 Xray 日志记录的域名/IP、端口、协议与时间展示；客户端上传、下载、累计值及日期范围用量来自官方持久累计值采样。

访问明细及原始日志最多保留 **7 天**；客户端分钟流量及每日访问数量汇总最多保留 **35 天**。第 8～35 天不提供逐条目标记录。区分没有访问、尚未采集、已过期、采集异常和断采数据，不将未知值显示为零。HTTPS 完整路径、内容、搜索词和每域名精确字节量不在首版范围内。

## 架构与接口

- 独立 Go 服务、React/TypeScript/Ant Design 6 页面、同源反向代理、版本适配脚本、SQLite。
- 浏览器从同源代理进入官方面板，脚本增加导航入口，右侧 iframe 展示监测页；地址查询参数保存选中状态。
- 独立入口为面板基础路径下的 `traffic-monitor/`；界面适配异常时保留独立入口和后台采集。
- 不修改官方二进制、内嵌前端或 Xray 内核；官方更新不覆盖扩展的程序、配置和数据库，重大布局更新通过版本适配器支持。
- 监测页及查询 API 必须验证原面板浏览器会话。后台专用 Token 仅用于固定读取请求，不替匿名请求认证，不进入浏览器和日志。2026-10-09 增补删除功能：仅专用删除接口支持 POST，须经会话验证、同源校验、一次性预览令牌确认，并在单事务内删除监测记录与流量。
- API 位于 `traffic-monitor/api/v1/`：`clients`、`summary`、`traffic`、`visits`、`health`；明细分页、限制查询范围并为时间和客户端建立索引。
- UTC 存储，默认按 Asia/Shanghai 选择日期，查询采用包含起始、不包含结束的区间。

## 采集与可靠性

- 默认每 10 秒采样累计上传/下载，首次仅建立基线，后续差值形成分钟汇总；不把接入前累计流量计入当天。
- 使用实例与稳定客户端身份关联计数，保存 email 时间映射。重命名、删除重建、计数回退、重置与跨日断采要明确记录。
- 通过官方持久 Xray 模板设置 access log，不修改重新生成的运行配置。
- 增量读日志，持久化文件标识、偏移和半行；数据写入及检查点原子提交，防止重启重复统计。处理轮转、截断、IPv6和异常行。
- 明细和汇总分开保存，清理 7 天前的明细不影响仍有效的 35 天汇总；原始日志也执行 7 天上限。
- 2026-10-09 增补：以域名匹配固定版本的社区规则集，展示常见服务名；按客户端和目标服务合并不同端口，目标维度汇总基于 7 天明细生成，不延长目标记录保留期。按客户端和日期删除全部目标的明细、访问次数、流量；保留采样基线、日志检查点和删除范围，避免旧记录重新进入统计。
- 采用 SQLite 回滚日志和串行写入，验证 WSL 挂载盘锁、事务和异常重启恢复；页面展示最后采集时间及兼容状态。
- 日期用量为采样统计，不作为账单级精确计量；不将跨日断采增量平均分配成精确日用量。

## 验收清单

- 旧服务、别名、自启动、进程、端口与确认的残留被清理；不触碰无关容器。
- 两个真实客户端访问受控 HTTP、HTTPS和 IP 目标，身份隔离及上传下载方向正确。
- 今天、自定义日期、跨日查询正确；第 8 天明细不可见，第 36 天汇总不可见。
- 日志轮转、截断、半行、重复读取、异常行、IPv6、服务/Xray重启不静默重复计数。
- 改名、删除重建、重置和断采正确关联或报告缺口。
- 主题、移动端、侧栏折叠、非根路径、刷新及前进后退正常。
- 未登录、退出及会话过期无法读取监测数据；Token 不泄漏。
- 官方发行包更新后配置和历史保持完整；未知布局有异常状态和可用的独立入口。
- 所有新项目文件都位于指定根目录。每项完成状态必须以实际测试证据为准。

## 2026-10-09 App、分钟范围与资源评估增补

- 以域名规则统一同一服务的网页、手机/平板 App、电脑软件、API 和媒体域名；参考固定版本的移动端规则，剔除无法可靠归属的共享服务。Telegram 的直接 IP 连接由官方专属 CIDR 辅助识别；保留原目标核查。
- 显示别名表与完整规则库分开，生成全部服务组目录及来源、版本、校验和、许可信息。官方升级继续不覆盖规则与监测历史。
- 查询和删除范围精确到北京时间分钟，包含用户选择的结束分钟，API 使用 UTC 包含起始、不含结束边界。上限仍是实际 35 天。
- 按用户补充的 1 核 CPU、1 GB 内存、20 GB 磁盘，最多 5 台设备、平时 1～2 台、月流量约 300 GB 评估。先在 WSL 绑定单 CPU，以隔离合成数据测量 7 万/70 万访问与 35 天分钟汇总；明确与实际 VPS 加密转发负载的差异。
- 根据测量优化分组查询、查询索引、页面轮询与闲置流量桶；日志积压明确显示状态。报告和测试数据都保存在项目根目录。

## 2026-10-10 REALITY 与官方累计清零增补

- 用 VLESS + TCP + REALITY + xtls-rprx-vision 创建本地受监测入站，经用户授权的私有远程出口访问百度、GitHub、YouTube。对比域名传递、IP 传递与客户端嗅探；按实际 access log 识别，不将伪装 SNI 当访问目标。
- 默认今天为空而其他日期仍有记录时，展示最近访问时间和跳转按钮。明确本机监测与远程代理服务器之间的数据边界。
- 在面板累计卡片新增清零，使用当前浏览器会话、官方 CSRF 及固定重置接口；预览客户端范围并显式确认。日期历史清理和官方累计清零分开，说明官方额度恢复/停用客户端重新启用的实际影响。
- 清零前后串行采样，提前持久化作废基线，失败或重启后也不能误算差值；日期历史继续保留，交接窗口标记数据质量。
- 兼容官方客户端创建时间精度变化，在身份中统一秒精度并事务迁移旧记录；保留流量、次数、别名、删除范围和最新采样基线。
- 实际清零验证限于专用停用的本地测试入站/客户端；用户给出的远程分享链接不授权远程面板管理，也不提供这种能力。

- 实时接口复用浏览器登录校验，按客户端和入站筛选；日期和目标条件只约束历史统计。首次采样、重置、间隔过长、采样过时均显示明确状态，页面约 10 秒更新实时、30 秒刷新历史。
- 真实流量验证使用专用本地 VLESS 客户端和有界上传下载；日期/所有客户端删除验证使用隔离监测数据库。测试不能清空现有真实历史。
