# Traffic Monitor implementation contract

All monitor endpoints live at `${webBasePath}traffic-monitor/` (base path normalized with leading/trailing slash). UI uses relative `api/v1/...`. Official panel is proxied at all other paths. UI document and API requests validate browser session with official `panel/api/server/status` and never use the collector token for this check. Static assets and adapter JS contain no secrets and may be public.

API responses: `{success:true,obj:DATA}` or `{success:false,msg:"..."}`. UTC ISO 8601 timestamps. Query: `start`, `end` (exclusive), `client_id`, `inbound_id`, and visits/targets `target`, `page` (1-based), `page_size` (default 50,max 200). Maximum interval 35 days; user timezone Asia/Shanghai. Date UI must convert date bounds to timezone-aware instants. Reads support GET/HEAD except reset-preview (GET only); `history/delete` and `panel/reset` support POST only. Invalid parameters 400, invalid session 401, CSRF/session mismatch 403, method 405, stale preview 409, content type 415, preview capacity 429, uncertain official reset result 502, unavailable service 503.

* GET `api/v1/clients`: array `{id:string,email:string,inbound_ids:number[],deleted:boolean,up:number,down:number,last_seen:string}`. Always includes current clients, including those with no sampled history. A deleted identity is returned only while it has retained visits (7d), nonzero sampled traffic (35d), or visit counts (35d); old official counter values alone do not keep it visible. Indexed existence checks apply retention immediately, even before pruning. Identity rows, aliases and deletion guards remain stored as needed for delayed-log attribution/replay protection. The UI defaults to current clients; “显示历史客户端” reveals retained deleted identities, disambiguated by last sync and identity suffix. Both query and deletion pickers follow this rule. Selecting all clients continues to include historical/unmatched records regardless of the display toggle.
* GET `api/v1/summary`: `{up:number,down:number,total:number,visit_count:number,panel_up:number,panel_down:number,monitor_started_at:string,detail_available_from:string,summary_available_from:string,quality:string[],timezone:string}`. `panel_*` are current counters independent of date selection. Quality codes: `before_monitoring`, `detail_expired`, `summary_expired`, `collection_gap`, `counter_reset`, `unmatched_identity`, `sampling`.
  Optional `last_visit_at` is the latest retained visit for the selected client/inbound, independent of date and target filters. The UI shows a date-jump hint for an empty interval without a target search. `counter_reset_window` marks a deliberate official reset and baseline handoff; it does not imply deleting history.
* GET `api/v1/traffic`: array `{time:string,up:number,down:number}`; interval bucket size may be automatically increased for long ranges (sum-preserving).
* GET `api/v1/realtime`: accepts only optional `client_id,inbound_id`; dates/targets/pagination parameters are rejected. Returns `{updated_at,sample_seconds,interval_seconds,online_available,stale,items:[{id,email,inbound_ids,status,rate_state,up,down,up_per_second,down_per_second}]}`. `up/down` are bytes in the latest sampling interval; rates are bytes/second. `status` is `online/offline/unknown`, `rate_state` is `ok/baseline/reset/gap/stale`. Unknown byte deltas/rates are null. Online status uses the official cached list, including idle active connections, rather than inferring status solely from byte movement. A successful online list may be empty. Collection failures or snapshots older than three sample intervals force unknown status and null rates. Browser session validation is unchanged; the data response reads a locked in-memory copy without querying history or re-fetching online state. The collector reads fixed POST `panel/api/clients/onlines` once per successful sampling cycle with no body; this official route only reads state. No additional history rows are written for live metrics.
* GET `api/v1/visits`: `{items:[{id:number,time:string,client_id:string,email:string,target:string,port:number,protocol:string,inbound:string,outbound:string,status:string}],total:number,page:number,page_size:number,expired:boolean}`.
  Each visit now also contains `destination:{key,name,domain,kind}`. `target` stays raw; `kind` is service/service_ip/domain/ip/local. `service_ip` identifies official exclusive Telegram networks; it uses the same service key as Telegram domains. Name-aware target filtering matches raw target, display name, canonical domain and service key.
* GET `api/v1/targets`: `{items:[{key,client_id,email,destination,visit_count,targets:string[],target_count,ports:number[],protocols:string[],inbounds:string[],first_seen,last_seen}],total,page,page_size,expired}`. Groups by stable client and destination service across ports; unknown client emails stay separate. Metadata arrays max50; target_count is exact. Limited to detail retention7d.
* GET `api/v1/rules`: `{source,commit,service_count,rule_count,ip_rule_count,app_rule_commit}` for the embedded offline ruleset. Website/app/API/media endpoints share one service key.
* GET `api/v1/history/preview`: explicit `start,end` required, optional `client_id`, minute-aligned, <=35d. `target` and `inbound_id` rejected. Future end freezes at the next current-minute boundary. Returns `{start,end,client_id,client_count,visit_count,summary_visit_count,traffic_buckets,up,down,total,preview_token,expires_at}`. A token is bound to the authenticated cookie set, expires5min, single use.
* POST `api/v1/history/delete`: JSON `{preview_token}` plus `X-Monitor-CSRF: <same token>`, matching `Origin` required, `Sec-Fetch-Site` must be same-origin when present. Revalidates official session and atomically compares the stored preview fingerprint before deleting. Response is the preview counts without token/expiry. Collector credentials cannot authorize this request. A monitor behind a separate TLS terminator must preserve same-origin scheme semantics; this WSL deployment directly serves HTTP on loopback.
  Deletes visits, minute visit counts and traffic for all targets/inbounds in the client/time range; preserves panel counters, baselines, aliases and checkpoints. Persistent deletion ranges suppress replay and overlapping sampled increments. Adds `history_deleted` summary quality. Raw source log files continue their7d lifecycle; no physical raw-file wipe.
* GET `api/v1/health`: `{status:string,panel_version:string,adapter_compatible:boolean,last_sample_at:string,last_log_at:string,monitor_started_at:string,detail_days:number,summary_days:number,timezone:string,issues:string[]}`. No paths, tokens, credentials, full upstream responses.

The latest UI removes the cumulative panel card and its reset dialog. `summary.panel_*` and the following previously implemented reset API remain for compatibility; the current UI uses sampled `summary.total` and minute-scoped `history/delete` only.

* GET `api/v1/panel/reset-preview`: only optional `client_id`, `inbound_id`; rejects dates/targets. Reads official current clients with the browser session, returns `{clients:[{id,email,inbound_ids,enabled,up,down}],up,down,disabled_count,preview_token,expires_at}`. At most 1,000 existing clients. The five-minute one-use token binds the session and exact identity/email/enabled scope; it deliberately does not freeze counter values because ongoing usage is also reset.
* POST `api/v1/panel/reset`: JSON `{preview_token}` plus matching `X-Monitor-CSRF`, same-origin `Origin`, and valid browser session. Rechecks scope, obtains official CSRF with the same cookie jar, and calls fixed `panel/api/clients/bulkResetTraffic` with selected emails. Neither preview nor write uses the collector token. Responds `{affected,client_count,synced}`. A false `synced` means the official operation succeeded but the follow-up monitor sample is pending. HTTP 502 means the upstream outcome could not be confirmed: refresh counters before retrying.
  A shared control lock excludes ordinary sampling during reset. First sample known pre-reset values, durably invalidate selected client baselines, submit the official write, then establish fresh baselines. Invalidation survives failure or restart. Reconciliation continues with a bounded context even if the browser disconnects. Monitor visits and sampled history remain intact; the uncertain handoff delta is not invented. Official reset restores remaining quota and may re-enable disabled clients; original quota ceilings and expiry settings remain. Client totals cover all their attached inbounds; independent inbound aggregate counters are outside this action.

Query and deletion UI use Shanghai wall-clock minutes and include the chosen final minute, converting it to exclusive API end by adding one minute. Selecting 09:30 through 09:30 queries [09:30:00,09:31:00). No rounding back to whole dates. The 35-day maximum uses elapsed duration including this final minute. Longer trend display buckets never expand the query bounds. UI refreshes after a 30-second idle interval and fetches only the active record tab; collector interval stays10s. Health issue `log_backlog` means a file reached the 2,000-record/4 MiB per-cycle batch limit with unread bytes remaining; further cycles catch up.

Config JSON (backend config load supplies defaults): `listen` (127.0.0.1:18080), `upstream` (http://127.0.0.1:12053), `web_base_path` (/), `panel_version` (3.10.2 bootstrap hint; actual upstream version is detected), `api_token_file`, `db_path`, `access_log_path`, `web_dir`, `timezone` (Asia/Shanghai), `sample_interval_seconds` (10), `detail_days` (7; max7), `summary_days` (35;max35), `xray_api_address` (127.0.0.1:62789 in the lab), `log_max_bytes` (67108864), `instance_id` (local). Config/secret paths are absolute in generated runtime config.

The collector also reads fixed `server/status` and `inbounds/list/slim` metadata routes to detect the actual version and map inbound tags. Client IDs combine instance, official numeric ID and creation timestamp to separate rebuilt identities. The creation timestamp is normalized to whole seconds (stored in milliseconds): official 3.9.0 can drop subsecond precision on first client edits. Startup transactionally migrates older keys and merges any split history, preserving totals, latest baselines, aliases, quality and deletion guards. IDs from another instance or a different official numeric ID remain separate. Inbound traffic filtering reports the full totals of associated clients, with `inbound_client_totals` quality metadata; it does not invent per-inbound byte attribution for a client attached to multiple inbounds.

Go module: `x-ui-tab/traffic-monitor`; executable `cmd/monitor` accepts `-config FILE`. Frontend lives `apps/traffic-monitor/web`, Vite outputs `web/dist` and uses relative base `./`. Root build script deploys dist to runtime/monitor/www. The `web/public/adapter.js` is copied into dist automatically and is served at `traffic-monitor/adapter.js`. It detects base from its script src. Adapter targets only verified v3.9.x DOM shape; injection is idempotent. Selected state: existing official `/panel/?monitor=traffic`; owned iframe fills content shell and preserves sidebar/header. Child messages (same origin only): `traffic-monitor:auth-required`, `traffic-monitor:theme` as needed. Independent UI includes back-to-panel link.

All writes and tool caches stay within the project root. Source scripts/env.sh before WSL build/test operations.

Docker adds optional `tls_cert_file` and `tls_key_file`, which must be configured together with absolute paths. When enabled the public monitor/proxy listener serves TLS 1.2+, and upstream cookies keep their original attributes plus `Secure`. Native WSL defaults remain HTTP. Direct TLS makes monitor deletion origin checks use the actual HTTPS request; arbitrary forwarding headers do not override the scheme.
